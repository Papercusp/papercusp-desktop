Revisions

This page tracks the substantive design decisions made during review. Each item links back to the review prompt that surfaced it and forward to the section that addresses it (or to the deferred bucket with the reasoning).

The plan has been through six rounds of external review so far. Each round’s reviewer was rigorous; their feedback is preserved here verbatim in summary so future readers can audit the design rationale. A seventh sign-off review is planned before implementation begins.

Round 1 (2026-05-08)

Section titled “Round 1 (2026-05-08)”

The first reviewer raised 18 items across top, mid, and lower tiers. We incorporated all of them in the revised plan with two non-trivial clarifications below.

Review itemResolutionSection
#1 Idempotency contract is the load-bearing assumption and barely engineeredAccepted in V1. Done-marker now hashes (configHash, plugin-version). Manifest distinguishes structural fields (force re-provision) from operational fields (apply hot). Default is structural (round 2 refinement).build-scripts § Idempotency
#2 Trust model is “the user reads the script source” — they won’tAccepted in V1, fully redesigned in round 2. Sandbox-by-default for all scripts (signed or not). Default-deny outbound network. Static-analysis warnings on common destructive patterns.build-scripts § Sandboxing
#3 Phasing inversion — share-semantics should ship before OAuthAccepted, deferred to V1.1. Phasing is PR ordering, not new code. Round 2 noted it can ship as ordering rather than blocking V1.open-questions § V1.1 ordering
#4 Schema evolution + .shape.json is unsolvedAccepted in V1. Per-property aliases: ["oldName"] array for renames; aliases: [null] for removals. Walked from current installed plugin’s manifest.share-semantics § Schema evolution
#5 Secret-but-intentionally-shareable case missingAccepted in V1. Field gets snapshotPolicy: "include" | "strip" | "warn-and-prompt", default strip. Publish CLI requires --include-secrets flag + per-secret confirmation when policy is include.share-semantics § Secret policy
#6 Cost estimates without enforcement = theaterAccepted, but radically. Dropped the field entirely from V1. Plugin authors document expected cost in their README. V1.1 adds a real provision.setup.budgetCap field wired to AWS Budgets via a substrate helper (~150 LOC, AWS-only). When that lands, cost is enforced, not advertised.build-scripts § What’s NOT in V1
#7 Concurrent / interrupted setup hand-wavedAccepted in V1. Per-(harness, plugin) lock file with PID + start timestamp. Stale-lock detection prompts user to run teardown before re-trying.build-scripts § Recovery
#8 OAuth refresh during operator-offlineAccepted in V1. Substrate ships ctx.oauth.token(field) helper that pre-emptively refreshes if expires_at is past or within 5 min, retries on 401-once. Plugins never think about expiry.oauth-integration § Refresh
#9 Build scripts vs compute:exec:* ambiguityAccepted, deferred to V1.1 (docs only). Pick (b): compute:exec:<bin> stays for in-action shell-outs (capability-gated, sandboxed). Build scripts are the lifecycle escape hatch (consent-gated, full host). Pure docs work.build-scripts § Relationship to compute:exec
#10 Pasted-PAT scope opacityAccepted in V1 for GitHub. When user pastes a token, substrate hits the provider’s introspection endpoint (GET /applications/<id>/token for GitHub), refuses if granted scopes < oauth.scopes, warns if scopes are more. Other providers as their OAuth integrations land.oauth-integration § Hybrid mode
Lower Audit log retentionAccepted in V1 with sane defaults. 1 year retention, 50MB per (harness, plugin) cap, oldest-first eviction. Formal policy + UI surfaces in V1.1.build-scripts § Audit logging
Lower Interactive subprocess banAccepted in V1. Manifest field provision.setup.requiresInteractive: false is enforced; substrate refuses scripts that try to read from stdin or open browser windows mid-run. Document workarounds (env-var-only credentials).build-scripts § Interactive subprocesses
Lower runAt: "fork" | "manual" | "first-action"Accepted, deferred to V1.1. Useful but not load-bearing for safety. Round 2 pinned the synchronization contract (action returns setup-required if invoked before first-action setup completes).build-scripts § Run timing (V1.1)
Lower Better dogfood — github-repo, not cloudflare-pages-hostedAccepted, deferred to V1.1. The CF Worker dogfood was bigger than necessary; github-repo’s repo creation as a build script exercises the full stack (OAuth + share-semantics + provisioning) more economically.open-questions § V1.1
Lower Quarantine invalidates cached approvalsAccepted in V1. When any snapshot is quarantined or retracted, the substrate clears all per-publisher trust entries for its publisher, forcing re-approval on next encounter.build-scripts § Trust lifecycle
Lower Marketplace moderation gapAcknowledged in V1, deferred to a separate spec. The plan now explicitly notes the moderation gap rather than assuming a reviewer exists.index § What this plan does NOT change
Lower Existing snapshot-model integrationAccepted in V1. Snapshot manifest gains requiresProvisioning: true field; fork-time substrate uses it to gate the consent flow. Plugin versions are pinned at fork against marketplace tampering (already part of the spec; restated here).index § Vision
Copy-edit index.mdx Q1-Q6 vs open-questions.mdx mismatchResolved by removing the duplicate question list from the index.index

Round 2 (2026-05-08)

Section titled “Round 2 (2026-05-08)”

The second-round reviewer concurred with the round-1 inclusions but pushed back substantively on two points and refined four others. The substantive pushbacks are reflected in the plan; the refinements landed without further debate.

Review itemResolutionSection
A. Sandboxing-only-for-unsigned is a misapplication of signingFully conceded. event-stream and xz-utils were the right examples — signed code can be malicious. Signing proves provenance, not safety. Sandbox is now default for all scripts; signing affects only consent-UI presentation, the visibility of the “trust this publisher” toggle, and the friction of escaping the sandbox as a power-user opt-out.build-scripts § Sandboxing
B. “Cost estimate with disclaimer” compromise is theaterFully conceded. The compromise was the worst option — looks like a feature, behaves like a comment. Dropped the field from V1 entirely. V1.1 adds budgetCap with a real AWS-Budgets helper.build-scripts § What’s NOT in V1
C. 30-day audit retention too shortAccepted. 1 year, 50MB per (harness, plugin) cap, oldest-first eviction.build-scripts § Audit logging
D. Aliases need to cover field removal, not just renameAccepted. A null entry in a property’s aliases array declares “this field was removed; .shape.json entries referencing it are dropped silently on fork.”share-semantics § Schema evolution
E. runAt: “first-action” needs synchronization contractAccepted. Action invoked before first-action setup completes returns { ok: false, error: "setup-required", setupUrl: ... }. Matches existing capability-denied response shape.build-scripts § Run timing (V1.1)
F. “All 18 in V1” risks delaying a shippable V1Accepted. Open-questions doc rewritten with explicit V1 / V1.1 / V2 split, justified per item by “what breaks publicly without this.” V1 line count target ~1,000–1,100 LOC; some items deferred to V1.1 (phasing, cost helper, runAt, dogfood swap, marketplace moderation, copy-edit).open-questions
G. Structural-vs-operational default should be structuralAccepted. Default to structural — worst case is friction (re-provision prompt on a benign edit), not silent stale state. Plugin authors flag fields operational: true to opt out.build-scripts § Idempotency

Pattern observations across rounds

Section titled “Pattern observations across rounds”

Every round added 3–6 substantive items that were genuine gaps. The gaps got smaller as rounds progressed:

  • Round 1: structural issues (idempotency contract, sandbox model, schema evolution, secret-shareable case)
  • Round 2: substantive refinements (sandbox/signing conflation, cost theater, audit retention)
  • Round 3: implementation-level holes (macOS asymmetry, IMDS/RFC1918, scriptHash comparison, marketplace moderation overconfidence, trust granularity)
  • Round 4: targeted gaps (smoke test, dev escape, ownership transfer, PG lock)
  • Round 5: surgical refinements of round 4 (Tauri sidecar, region templating, recordResource helper, key rotation, queue overflow)
  • Round 6: refinements of round 5 (named dev path, preset maintenance, teardown dispatcher, key-rotation attestation)

Convergence is happening. Round 7 should be sign-off-only. If it surfaces substantive new issues, scope is re-evaluated.
