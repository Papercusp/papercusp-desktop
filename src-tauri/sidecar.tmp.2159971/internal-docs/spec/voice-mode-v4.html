Voice mode v4

Voice mode is the audio modality on top of the v5 Operator. It lets users hear Operator’s suggestions, cancel auto-fires by saying “cancel,” and invoke commands like operator approve foo from anywhere without opening the panel.

This page documents the v4 architecture (May 2026). For design rationale, see /tmp/voice-mode-plan-v4.md.

Section titled “STT (speech → text)”

Voicemode (Whisper)Local on :2022Audio never leaves machine✅ when reachable

Endpoint resolution (per voice-engines.ts):

  1. mcp__voicemode__service whisper status (when MCP probe is available)
  2. VOICEMODE_WHISPER_URL env var
  3. http://localhost:2022 default

No silent fall-through — if probes fail, settings shows a clear “not detected” message pointing at mcp__voicemode__service whisper start.

Mid-session disconnect: voice-engine-health.startSttHealthMonitor polls /health every 30s; transitions fire role="alert" toasts.

TTS (text → speech)

Section titled “TTS (text → speech)”
EngineWhere it runsStreamingCostDefault
Kokoro (Voicemode)Local on :8880No (full payload)$0✅ when reachable
BrowserOS-shipped voicesNative$0Fallback
ElevenLabsCloudYes (MSE)~$0.18/1k charsOpt-in (BYO key)
OpenAICloudNo (buffered)~$0.015/1k chars (tts-1)Opt-in (BYO key)

API keys live in ~/.papercusp/credentials.json — never in voice-prefs (which travels on snapshots). Mask-on-GET / preserve-on-PUT semantics.

ElevenLabs streaming uses MediaSource Extensions (per v4 §1.2.6) for sub-400ms first-byte. Cancellation is via audio.pause() + removeSourceBuffer() + AbortController on the underlying fetch. Safari falls back to buffer-then-play.

OpenAI uses buffered playback (no streaming endpoint as of tts-1). 6 preset voices (alloy/echo/fable/onyx/nova/shimmer); two models (tts-1 cheap, tts-1-hd better quality).

Cost tracking

Section titled “Cost tracking”

Per-call spend recorded in Postgres (harness_shared.operator_tts_spend, migration 020 — was previously <papercuspRoot>/system/operator/tts-spend.json but the JSON file raced under multi-tab usage). The JSONB payload shape:

  • Soft cap (default $5/day): one assertive toast per UTC day, dedup’d via softCapAcknowledgedDate
  • Hard cap (default $20/day): auto-fall-back to Kokoro/browser, toast user
  • Rollover: lastSpendDate field — comparing on every speak() catches sleep-through-midnight + timezone travel

Voice consumer priority

Section titled “Voice consumer priority”

VoiceAppBridge consumer registry (per v4 §2b):

Highest-priority registered consumer wins. If it has an onUtterance handler (e.g. background-toast looking for “cancel”), it processes the utterance directly. Otherwise the consumer just suppresses lower-priority routing.

Multi-tab leader election

Section titled “Multi-tab leader election”

voice-leader.ts BroadcastChannel-based protocol (per v4 §2i):

  1. Election + heartbeat (Phase 1): chrome boot opens BroadcastChannel('operator-voice'), posts announce, waits 250ms, lowest tabId wins. Leader heartbeats every 5s; followers re-elect after 12s of silence.
  2. Focus transfer (v1.5): requestVoiceLead() — when user opens the panel in a non-leader tab, that tab requests the lead, current leader yields, requesting tab becomes leader. Spoken output follows user attention.
  3. Availability guard: Safari private windows / WebViews lacking BroadcastChannel fall back to single-tab mode + settings note.

Election runs async during chrome boot; render is not blocked.

Wake-word operator <verb> intents

Section titled “Wake-word operator <verb> intents”

Strict 2-word prefix; verb whitelist (per v4 §2f):

UtteranceEffect
operator open / operator showOpen the panel
operator scan / operator status / operator what's pendingOpen + trigger scan
operator approve <slug>Resolve standing approval (single-match)
operator approve <slug> <cap>Explicit cap pick (e.g. operator approve foo tasks-write)
operator across workspacesSpeak per-workspace card counts

Approve disambiguation rules (per v4 §2f):

  1. Filter to candidates with targetHarness === slug
  2. Filter out firstShownAt === null (user must have seen it)
  3. If explicit cap: must be voice-eligible (2-segment, alphabetic-only) AND match exactly one
  4. If no explicit cap: auto-pick when 1 remains; otherwise refuse with disambiguation prompt

Cap eligibility: tasks:write ✓, secrets:read:OPENAI_KEY ✗ (3+ segments + underscore).

Cancel race + visual ring

Section titled “Cancel race + visual ring”

Per v4 §2c: when voice mode is on AND speakBackgroundToasts is on:

  • Visual ring extends to 8s (matches commit deadline)
  • “cancel” utterance during the window cancels speech + dispatch + writes undo_cancel audit
  • Visual button always available + authoritative

When voice mode is off OR toggle is off: visual ring stays at 5s, commit at 5s.

The 8s extension absorbs worst-case STT latency (~1.5s on slow CPUs) without penalizing click-cancel users on default config.

Per-role voice mapping

Section titled “Per-role voice mapping”

Voices keyed on role (not slug). All instances of the worker role share one voice; per-slug overrides (worker@papercup-coding-foo) are v1.5 (the lookup chain in voiceForRole already supports them — settings UI exposure pending).

Roles in v4:

  • system:operator — Operator’s main voice
  • system:operator-nudge — calmer voice for budget/breaker/pause
  • harness — generic fallback for receiving-flips when template-role missing
  • worker / validator / orchestrator / etc. — substrate roles

TTS engine failure handling

Section titled “TTS engine failure handling”

voice-engine-health.ts tracks consecutive errors per session:

  • 3 consecutive errors → mark engine disabled
  • One-time role="alert" toast: “Voice mode silently failed; switching to visual.”
  • Subsequent speak() calls become no-ops
  • Re-enable from /settings/voice (probes the engine + resets counter)

STT capture loop (Voicemode whisper path)

Section titled “STT capture loop (Voicemode whisper path)”

stt-voicemode.ts MediaRecorder loop:

  • Codec: 16kHz mono webm/opus (mp4/ogg fallback)
  • VAD: RMS > -45 dBFS triggers voice; silence > 700ms ends utterance
  • Hard window: 30s force-finalize (avoid runaway recording)
  • Min chunk: 1.5s floor (avoid false-positive end on mic warmup)
  • Min size: 5KB blob threshold (skip noise-only chunks)

Each finalized chunk POSTs to /v1/audio/transcriptions and the returned text fires onUtteranceFinal().

Realtime operator voice in the pui (voice-realtime-tui-2026-06-05)

Section titled “Realtime operator voice in the pui (voice-realtime-tui-2026-06-05)”

The terminal workbench has BOTH voice modes:

  • PTT (v): capture → Whisper STT → operator-converse → operator-tts (engine + voice from voice prefs — ElevenLabs when selected) → playback.
  • Realtime (V, any tab): a raw ElevenLabs Conv-AI WebSocket session. GET /api/agent-mcp/operator-elevenlabs-ws-init mints the signed URL server-side (key never leaves the operator), claims the voice lease (kind tui — one live listener across desktop/mobile/pui), and returns the shell-mode payload (language-pin override only). The Rust client (apps/tui/src/voice_convai.rs) streams ~250 ms pcm_16000 mic chunks up, plays audio events gap-free, answers ping, stops playback on interruption (barge-in), and serves the ask_operator client tool over the existing operator-converse SSE — the same brain loop as the desktop’s browser clientTool. Transcripts persist into the SAME operator conversation (sources voice_stt/voice_tts, tags stripped).

Requirements: fullAgentEngine = elevenlabs-conv + elevenLabsAgentId in /settings/voice and an ElevenLabs API key — the same config the desktop full-agent mode uses. Without them V surfaces the route’s hint as a toast.
