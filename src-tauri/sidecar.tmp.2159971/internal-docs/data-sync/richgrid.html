RichGrid

Zero is being retired — historical reference

Zero / zero-cache / ZQL named-queries / WebSocket push is on the retirement path. The shipping desktop app uses SSE-primary sync (the :3070 Hono host pushes invalidate/update over Postgres LISTEN/NOTIFY); zero-cache is not run on desktop. Treat this page as historical reference. Source of truth: apps/operator/providers/HarnessZeroProvider.tsx (transport-selection doc-comment) + the root CLAUDE.md deployment-model section.

When to reach for RichGrid

Section titled “When to reach for RichGrid”

Use RichGrid for any panel that renders a list of rows where each row has the same columnar structure. It replaces every <table> and every hand-rolled .map() => <div className="row"> in the codebase.

Do not use RichGrid for:

  • Card-grid feeds where each card shows a different shape (ArchitectInbox).
  • Kanban / column-board layouts (BoardView).
  • Master-detail explorers where the “list” is actually a sidebar to an embedded editor (MemoryBrowser, IdentityPanel, PromptsTab, CollectionTab).
  • Image galleries (ScreenshotsPanel).
  • Timeline / chronological streams (PulseFeed, FeatureTimelinePanel).

If you find yourself adding a “second row of metadata under each grid row” you’re probably building one of the above and should use a card layout instead.

Width is fr units, not pixels

Section titled “Width is fr units, not pixels”

width: 1.3 means 1.3 fractions of the available width. The grid uses CSS Grid’s grid-template-columns: repeat-fr under the hood. Pixel widths are not supported by design — content adapts to the panel’s container.

Sort key

Section titled “Sort key”

sortKey is a string — the upstream field name the data source should sort by (sortKey: 'ts'). It is not a deriving function; the grid passes the string back to you via onSortChange, it does not read the row.

Sort is controlled: a column’s header is only clickable when it has a sortKey and you pass onSortChange. RichGrid does not sort the data itself — it emits a SortState ({ column, dir } or null) and you apply it. Clicking cycles defaultSortDir → opposite → unsorted (null). Pitfall: rowProps + a CSS class with display: grid

Section titled “Pitfall: rowProps + a CSS class with display: grid”

If rowProps returns { className: 'h-issue' } and the legacy class has its own display: grid, that grid clashes with RichGrid’s internal cell grid and every cell renders on top of itself.

Patterns: virtual rows

Section titled “Patterns: virtual rows”

For grids that may show >500 rows (audit logs, agent runs across years), pass virtualMode (a { virtualizer, totalRows, rowAt } object) instead of rows. You own the TanStack virtualizer + the windowed rowAt(index) lookup; rowAt may return undefined for not-yet-loaded rows, in which case RichGrid renders renderLoadingRow (or a “loading…” line). Row sizing defaults to rowMinHeight (36px); override per grid if rows are taller.

Multi-expand

Section titled “Multi-expand”

RichGrid supports per-row expanded detail via renderExpandedRow plus an expansion-key prop. The caller fully owns the expanded-state — RichGrid does not toggle on click. Use expandedRowKey (single id) or expandedRowKeys (a ReadonlySet<string> for multiple rows; the two are unioned):

Testing a migrated panel

Section titled “Testing a migrated panel”

After migrating from a hand-rolled list:

  1. Visual: open localhost:3055/harness/<slug> and confirm columns line up. If a cell is blank, check the render: (row) => vs ({ row }) bug above first.
  2. Sort: click each header with a sortKey and confirm direction indicator updates.
  3. Click: confirm onRowClick fires (and that buttons inside cells stop propagation).
  4. Empty state: rows = [] should render the grid header with no content; provide a sibling empty-state component if the panel needs one.
